# 업무 6: 감각 되먹임 기반 S자 카빙 강화학습 설계 (v1, 2026-09-23)

> 상위 컨텍스트: [00_master_prompt.md](00_master_prompt.md), [05_training_evaluation.md](05_training_evaluation.md).
> 구현: `flyski_sim/rl_task.py`(환경), `flyski_sim/train_rl.py`(PPO). 근거: RESEARCH_NOTES 34~36번.

## 목표
초파리가 다리로 스키 플레이트를 세워(엣징) 카빙턴으로 냄새 게이트를 좌우로 통과하며 S자로 내려가는 행동을 강화학습으로 얻을 수 있는지 확인한다. 이번 단계는 "가능성"만 본다(1회 짧은 학습). 제대로 된 학습은 다른 PC에서 한다.

## 전제(이번에 확인된 물리)
- 스키 스탠스: 좌/우 세 발끝이 일직선, T2가 판 정중앙(34번). 액션은 스탠스 대비 오프셋.
- 카빙: `edge_grip.py`의 엣지 그립 + 카빙 호 모델(35번). 엣지 ±20°에서 엣지 쪽으로 돌고 skid 0.06. 10°는 그립이 약하고 30°는 불안정.
- **이 스케일의 카빙 자세는 몸을 거의 세우고 다리로 판만 세우는 것**(프루드 수가 작아 필요한 몸 기울기 ~1.5°). 몸통을 기울이면 다리가 휘어 판은 눕는다. 정책이 배워야 할 핵심은 다리 앵귤레이션이다.

## 환경
| 항목 | 값 | 이유 |
|---|---|---|
| 코스 | 알파인 평면 15°, 60 x 16cm, 폴라인 +x | 모글 없이 카빙만 먼저 |
| 게이트 | `OdorField` 간격 8cm, 좌우 진폭 3cm, 통과 반경 1.5cm, 순차 점화 | 사람이 궤적을 정하지 않음(00번 원칙) |
| 스폰 | 코스 위쪽 끝에서 2cm, 폴라인 방향 | |
| 정책 주기 | 10ms(물리 0.2ms x 50) | 2ms면 파이썬 훅 비용이 커짐 |
| 에피소드 | 3초(300 스텝) | 약 40~50cm, 게이트 5~6개 |

## 관측(감각 되먹임, 147차원)
| 감각 | 내용 | 차원 |
|---|---|---|
| 고유감각 | 다리 주 관절각(스탠스 대비), 관절속도 x0.05 | 42 + 42 |
| 전정 | 몸 기준 중력 방향, 각속도 x0.05, 선속도 x0.05 | 9 |
| 스키 감각 | 좌/우: 부호 있는 엣지각(+ = 오른쪽 엣지), 옆미끄럼 비율, 접지 여부, 그립 사용률 | 8 |
| 후각 | 좌/우 더듬이 농도, 좌우 차 x10, 직전 대비 변화 x10 | 4 |
| 직전 액션 | | 42 |

게이트 위치/방향 같은 특권 정보는 넣지 않는다. 게이트는 후각(좌우 농도 차 = 방향, 시간 변화 = 접근 여부)으로만 찾아야 한다. 초파리가 실제로 좌우 더듬이 농도 차로 조향한다는 점(25번의 후각 경로)과 맞춘 선택이다. 학습이 너무 어려우면 첫 단계 커리큘럼으로 "다음 게이트 방향 벡터"를 잠깐 넣었다가 빼는 방법이 있다.

## 액션(42차원)
다리 주 관절 42개(다리당 coxa_abduct, coxa_twist, coxa, femur_twist, femur, tibia, tarsus)의 스탠스 대비 오프셋, [-1, 1] x 0.3rad. 날개/머리/복부/흡착/tarsus2~5 힘줄은 0.

## 보상(스텝마다 합산, `REWARD_WEIGHTS`)
| 항목 | 가중치 | 정의 | 의도 |
|---|---|---|---|
| progress | 0.005 | 폴라인 속도(cm/s) | 내려가기. 0.02면 직진만으로 게이트 보상을 압도해서 낮춤 |
| odor | 10 | 두 더듬이 평균 농도의 증가량 | 퍼텐셜 기반 셰이핑(합이 망원급수라 최적 정책을 바꾸지 않음) |
| gate | +10 | 활성 게이트 통과 | 코스 준수의 주 보상 |
| gate_miss | -3 | 통과 못 하고 게이트 x를 1cm 넘김 | 직활강 억제 |
| carve | 0.3 | 카빙 품질 q = (1 - skid) x clip((엣지 - 5°)/15°) (접지, 5cm/s 이상일 때) | 스키딩 말고 엣지로 돌기 |
| edge_turn | 0.5 | q, 단 카빙 방향(엣지 쪽)이 다음 게이트 쪽과 같을 때만 | "엣지를 세워 회전 성공" |
| alive | 0.05 | 매 스텝 | |
| ctrl | -0.01 | 액션 제곱 평균 | 떨림 억제 |
| fall | -5 | 종료 시 | |

종료: 몸 up 벡터와 사면 법선 내적 < 0.5, 스키 외 몸 부위가 눈에 닿음, 코스 이탈, 물리 발산.

## 알고리즘(이번 1회)
PPO(stable-baselines3), MLP [256, 256], log_std_init -1, n_steps 256 x 10 env, batch 640, epoch 5, lr 3e-4, gamma 0.99. 시간 예산 40분.

## 알려진 위험(보상 해킹 감시)
- carve/edge_turn은 "게이트와 무관하게 엣지만 세우고 천천히 가기"로 얻을 수 있다. 5cm/s 속도 하한과 게이트 보상이 견제하지만, 학습 후 게이트 통과 수와 같이 봐야 한다.
- 엣지 그립은 현상론 모델이다. 정책이 모델의 허점(예: 30° 근처 튐, 착지 순간 N 상한)을 쓰는지 롤아웃 GIF로 확인한다.
- progress를 너무 낮추면 멈춰 서서 alive만 모으는 정책이 나올 수 있다(alive 0.05 x 300 = 15).

## 다른 PC에서 제대로 학습할 때
- 병렬 env 수 = 코어 수 - 2 정도. 이 워크로드는 env마다 단일 스레드 CPU 물리라 코어 수에 비례한다.
- i5-13400(P6+E4, 16스레드) vs Ryzen 9 5900X(12코어 24스레드): 코어 하나 성능은 13400 P코어가 약간 빠를 수 있지만 전체 처리량은 5900X가 더 클 가능성이 크다. 추정이니 두 PC에서 `python -m flyski_sim.rl_task`의 policy steps/s와 병렬 실행 합계를 재서 고를 것.
- 1순위 속도 개선: `edge_grip.py`의 서브스텝 파이썬 루프(정책 스텝당 50번)를 벡터화하거나 C 콜백(mjcb_passive)으로 옮기기.
- 커리큘럼: 게이트 진폭 1cm부터 3cm로, 그다음 모글.
- 커넥톰 정책은 MLP 정책이 게이트를 통과하게 된 뒤에 교체하고, real/shuffled 비교는 그 안에서 한다(05번).
