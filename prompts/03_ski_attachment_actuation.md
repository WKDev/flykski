# 업무 3 — 스키 결합 통합 & flybody 액추에이션 (v2, 구 "조종 파라미터" 업무 대체)

> 상위 컨텍스트: [00_master_prompt.md](00_master_prompt.md). **v1의 `ControlInput`/`SkiController.step` 추상 제어 API는 폐기한다.** flybody는 관절 액추에이터로 직접 구동되며, 엣지각·하중배분 등은 그 결과에서 파생 계산하는 텔레메트리로만 존재한다.

> **정정(교차검증 반영)**: flybody 전신 모델은 67 body parts / 66 joints / 102 DoF이지만, **이는 액션 공간 차원과 동일하지 않다.** flybody 공식 예제의 보행(walking) 태스크 액션 차원은 **59**이며(비행 태스크나 전신 태스크는 다른 차원을 가질 수 있음), 실제 값은 선택한 flybody 태스크 설정(`flybody.fly_envs`)에서 그대로 가져와야 한다. 이 문서 전체에서 "102"라는 숫자를 하드코딩하지 말고 `env.action_spec()`(또는 동등 API)에서 조회한 `action_dim`을 사용한다.

## 목표
업무2에서 정의한 스키를 flybody MJCF에 실제로 병합하고, (a) 스키-설질 접촉 물리를 업무1의 설질 파라미터와 연결하며, (b) flybody의 네이티브 관절 액추에이터(차원 수는 선택한 태스크에 따름, 예: 보행=59)를 그대로 액션 공간으로 노출하고, (c) 엣지각/하중배분/팁-테일 하중 같은 "스키 지표"를 시뮬레이션 상태에서 파생 계산하는 텔레메트리 계층을 만든다.

## 배경·근거
FlyGM/flybody 계열 선례는 신경 출력을 곧바로 관절 액추에이터에 매핑하는 구조로 실제 걷기/날기를 성공시켰다. v1처럼 "무게중심 압력 → 플레이트 하중 → 엣지각"이라는 중간 추상 레이어를 액션 공간으로 두면, 이미 검증된 flybody의 관절 제어 체계와 어긋나고 재사용 이점을 잃는다. 따라서 액션 공간은 flybody 네이티브 관절 토크로 통일하고, 사람이 이해하기 쉬운 스키 지표는 **관찰/보상/분석 전용 파생값**으로 내린다.

## 상세 요구사항

### 1) 스키-설질 접촉 통합
- 업무2에서 부착한 스키 지오메트리(기본안: 다리 6개 각각의 미니 스키)의 바닥면에 대해, 기본 tarsus-지면 접촉 대신 스키 밑면-지형 접촉으로 콜라이더를 교체한다.
- 접촉 시 마찰계수는 업무1의 `TerrainQuery.get_height_and_normal()`이 반환하는 `snow_type/snow_params`를 그 위치의 MuJoCo 접촉 파라미터(`friction`, `solref`/`solimp` 등)에 매 스텝 반영한다(설질이 위치마다 다르므로 정적 XML 값이 아니라 런타임 갱신 필요).
- **침투 저항(파우더 등)에 대한 알려진 한계**: `solref`/`solimp` 같은 표준 접촉 솔버 파라미터는 "얼마나 깊이 파고들수록 저항이 커지는" 깊이-의존 점성 항력을 정확히 재현하지 못한다. 1차 구현은 솔버 파라미터 튜닝으로 근사하되, 파우더 설질에서 체감 가능한 침투 저항이 나오지 않으면 **접촉점의 침투 깊이를 계산해 `xfrc_applied`(외력 직접 주입)로 보조 항력을 추가**하는 방식으로 확장한다. 이 확장 여부와 근사 품질을 반드시 벤치마크로 검증하고 문서화한다.
- 모글 둔덕과의 충돌로 스키가 공중에 뜨는 상황(에어타임)을 감지하고 착지 시 충격을 업무2의 `flex_stiffness`에 따라 감쇠하는 로직을 포함한다.

### 2) 액션 공간 = flybody 네이티브 액추에이터
- flybody가 제공하는 관절 토크(또는 위치 서보) 액추에이터 인터페이스를 그대로 사용한다. 스키 부착으로 인해 늘어난 관성/접촉 변화에 맞춰 기존 사전학습 컨트롤러의 게인이 부족하면, 재조정(fine-tune) 절차를 별도로 문서화한다.
- 디버그용 수동 조작 모드(키보드/게임패드로 몇 개의 상위 파라미터, 예: "좌우 회전 편향", "속도"를 흉내내는 스크립트 정책)를 제공해, 커넥톰 없이도 스키+지형 통합이 정상 동작하는지 사람이 확인할 수 있게 한다 — 단, 이 스크립트 정책은 디버그 전용이며 최종 액션 공간은 여전히 관절 토크임을 명시한다.

### 3) 파생 텔레메트리 (관찰/보상/분석용, 액션 아님)
시뮬레이션 상태(관절각, 접촉력, 스키 자세)로부터 매 스텝 아래를 계산해 로깅·관찰 벡터·보상 함수에 제공한다. 인덱스 `i`는 부착된 스키 개수(N=6 기본안이면 다리 6개, N=2 확장이면 좌/우 2개)만큼 존재하며 개수를 하드코딩하지 않는다:
- `effective_edge_angle_i_deg`: 스키 i 밑면 법선과 지형 법선 사이 각도.
- `plate_load_share_i`: 스키 i가 받는 총 수직 접촉력 비율(모든 스키 합 = 1).
- `fore_aft_pressure_center_i`: 스키 i 접촉 영역 내 압력 중심의 팁-테일 상대 위치(-1 테일 ~ +1 팁).
- `center_of_mass_projection_vs_support_polygon`: 무게중심 투영이 지지기저면(활성 접촉 스키들이 이루는 다각형) 안에 있는지(전복 판정에 사용).
- `is_fallen`: 몸통 자세각이 임계치를 초과하거나 무게중심이 지지기저면을 벗어난 상태가 일정 시간 지속되면 True.

### 4) 실행 주파수
- 물리 스텝은 flybody 기본 설정(고주파, 보통 ms 단위)을 따르고, 텔레메트리 계산은 물리 스텝마다 또는 다운샘플링된 주기로 수행할지 명시한다(업무4/5의 정책 실행 주파수와 맞춰 문서화).

## 인터페이스 계약
```
FlySkiEnv.action_dim -> int   # flybody 태스크에서 조회, 하드코딩 금지 (보행 태스크 기준 예: 59)
FlySkiEnv.n_skis -> int       # 기본 6, N=2 확장 시 2
FlySkiEnv.step(joint_actuation: np.ndarray[action_dim]) -> Observation, done
Observation = {
  proprioception: {joint_angles, joint_velocities},
  ski_telemetry: { effective_edge_angle_deg[n_skis], plate_load_share[n_skis],
                   fore_aft_pressure_center[n_skis], is_fallen },
  odor: { concentration, gradient_xyz },   # 업무1 OdorField 그대로 전달
  terrain_local: { slope_deg, snow_type }
}
```
- 이 `Observation`이 업무4 커넥톰 컨트롤러의 입력 스키마이자 업무5 학습 루프의 관찰 공간이다. 필드 추가/변경 시 두 문서를 함께 갱신한다.

## 산출물
- 스키 부착 flybody MJCF + 런타임 설질 접촉 파라미터 갱신 로직.
- flybody 네이티브 액추에이터를 그대로 노출하는 `FlySkiEnv` (Gymnasium 스타일 권장).
- 파생 텔레메트리 계산 모듈 + 단위 테스트.
- 디버그 수동 조작 데모.

## 구현 현황
`flyski_sim/telemetry.py`(`compute_ski_telemetry`)로 파생 텔레메트리 구현·검증 완료 (2026-09-23, `python -m flyski_sim.telemetry_test`). 구현 과정에서 스키가 실은 땅에 안 닿고 있었던 버그(RESEARCH_NOTES.md 14번)와, 엣지각 계산이 다리마다 제각각인 로컬 프레임 때문에 44°씩 잘못 나오던 버그(15번)를 둘 다 잡았다 — 두 문제 다 "claw의 로컬 프레임을 세계 프레임처럼 취급"한 게 근본 원인이었다.

## 수용 기준
- [x] `action_dim`/`n_skis`를 하드코딩 없이 flybody 태스크/업무2 설정에서 조회해 사용함(코드 검토로 확인, `env.action_spec()`/`len(task.skis)`).
- [x] 스키 부착 후에도 물리 스텝이 발산(NaN, 폭주)하지 않고 안정적으로 시뮬레이션됨(평지 200스텝, 경사 150스텝, **실제 스키-지면 접촉이 있는 상태에서** 검증 — "최소 수천 스텝"까지는 아직 안 늘려봄, 후속 과제).
- [x] 설질이 다른 두 구간을 지날 때 접촉 마찰 파라미터가 실제로 다르게 적용됨(업무1에서 구현·검증 완료, `apply_snow_friction_at`).
- [x] `effective_edge_angle_deg`가 스키를 수동으로 기울이는 디버그 조작에서 기대한 부호/크기로 변함(0°→60° 수동 회전 시 정확히 반영, 정상 기립 시 평균 1.2°로 검증).
- [x] `is_fallen`이 실제 넘어짐 상황에서 정확히 True가 됨(90° 강제 전도 시 확인). 몸통 기울기(threshold) + 지지기저면(support polygon) 이탈 두 조건 OR로 판정.
- [x] `plate_load_share`가 6개 스키에 걸쳐 합=1로 정규화됨을 확인(cfrc_ext의 수직 반력 성분 기반).
- [x] `xfrc_applied` 보조 항력 경로 구현·검증 완료(2026-09-23, `flyski_sim/drag_test.py`). 같은 속도에서 파우더 항력이 아이스보다 30배 강함을 확인, 파우더+모글 지형 결합 상태로 150스텝 안정성도 확인. 처음엔 계수 스케일을 잘못 잡아 즉시 발산했다가 재조정(RESEARCH_NOTES.md 16번).
- [ ] 디버그 수동 조작으로 넘어지지 않고 일정 거리 이상 활강 가능 — 미구현(지금까지는 전부 zero-action 정적 안정성 테스트, 실제 조향 입력 루프는 아직 없음).
